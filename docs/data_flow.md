# EOIP Data Flow Description

## 1. Purpose

This document describes how data moves through the Energy Operations Intelligence Platform from source generation to transformation, storage, analytics, and dashboard presentation. It is intended to guide both technical understanding and diagram creation for a visual process flow showing the full operational lifecycle of the platform.

---

## 2. Overview of the Flow

The EOIP data flow can be described as a pipeline with seven stages:

1. Data generation
2. Data ingestion
3. Validation and cleaning
4. Database storage
5. Analytical processing
6. API exposure
7. Dashboard consumption and decision support

This flow ensures that operational information is transformed from raw signals into reliable, ready-to-use insight for plant operations, maintenance, anomaly investigation, and executive review.

---

## 3. Stage 1: Data Generation

The process begins with renewable-energy operational data generated from a variety of sources. These sources include:

- plant-level generation data
- inverter and equipment telemetry
- weather and irradiance information
- alarms and incidents
- equipment maintenance logs
- transformer, feeder, and site metadata
- operational event records and status updates
- tariff or financial contextual data

This data reflects the conditions of the solar energy portfolio and forms the foundation for operational monitoring and analytics.

---

## 4. Stage 2: Data Ingestion

Generated data is collected into the EOIP platform through the ingestion layer. This layer is designed to receive records in a structured or semi-structured format and prepare them for standardization.

During ingestion, the system ensures that data is mapped into canonical objects such as:

- plant records
- equipment records
- weather observations
- telemetry measurements
- incidents and alarms
- forecast input data
- maintenance actions

The ingestion step may occur from synthetic data files, ETL outputs, or structured application datasets used for demonstration and evaluation.

---

## 5. Stage 3: Validation and Cleaning

Before the data is committed to the database, it passes through validation and cleaning logic. This step ensures the integrity of the platform and reduces downstream errors in analytics.

Validation tasks include:

- checking required fields
- verifying timestamps are valid and consistent
- ensuring plant and equipment identifiers exist
- checking unit consistency and measurement ranges
- identifying duplicates or missing values
- quarantining invalid rows for investigation
- normalizing inconsistent labels or naming patterns

The purpose of validation is to ensure that the analytics engine is fed clean and reliable operational data.

---

## 6. Stage 4: Storage in PostgreSQL / TimescaleDB

Once validated, the data is loaded into the database layer. EOIP uses PostgreSQL with TimescaleDB for time-series-aware storage and relationships between operational entities.

The database stores multiple categories of data, including:

- plant and site metadata
- equipment hierarchy and asset structure
- telemetry time series
- alarm and event history
- weather and environmental conditions
- maintenance records
- forecast outputs
- model evaluation results
- recommendation metadata

This layer supports both time-based query operations and relational joins between operational entities. It becomes the central source of truth for historical analysis and dashboard reporting.

---

## 7. Stage 5: Analytical Processing

At this point, the system begins producing intelligence from the stored data.

### Forecasting

Forecasting models use historical operational and weather data to estimate expected generation or future conditions. Forecasts are used to compare expected versus actual performance and to flag operational deviation.

### Anomaly Detection

Anomaly detection evaluates new or historical telemetry to identify unusual changes in behavior. This can highlight plants or assets that deserve investigation.

### Predictive Maintenance

Predictive maintenance logic reads from equipment condition, performance history, and event records to prioritize assets with elevated risk or maintenance attention requirements.

### Equipment Health Scoring

The equipment health processes combine metrics from multiple data sources to create health scores that summarize asset condition and risk.

### Recommendation Generation

Final recommendations are generated by combining model outputs, asset health views, event context, and operational priorities. These recommendations are then surfaced to users for review and action.

---

## 8. Stage 6: API Exposure

After analytics outputs are produced, they are exposed to consumers through the FastAPI layer. This service layer organizes access to operational and analytical data in a consistent, structured format.

The API is used to provide:

- health checks and service readiness
- operational metadata and summaries
- plant and equipment lookup endpoints
- analytics-related query responses
- dashboard data access for the frontend application

This decouples the user-facing application from direct database logic and provides a cleaner integration boundary for future services and clients.

---

## 9. Stage 7: Dashboard Consumption and Decision Support

The final stage of the data flow is the presentation layer. EOIP uses a Streamlit dashboard that reads operational data, analytics results, and recommendation outputs to create a user experience for decision-makers.

Dashboards are organized around personas and operational use cases, such as:

- executive overview
- asset performance review
- incident and alarm investigation
- maintenance prioritization
- anomaly and forecast review
- recommendation center
- data quality and operational health checks

This final layer transforms structured information into understandable visual summaries so users can identify issues, monitor trends, and decide on action.

---

## 10. End-to-End Flow Summary

The data pipeline can be summarized as:

Data Sources -> Ingestion -> Validation and Cleaning -> PostgreSQL / TimescaleDB -> Analytics Engines -> API Service -> Streamlit Dashboards -> Operational Decisions

This is the fundamental operational lifecycle of EOIP. It ensures that data is not only collected, but also cleaned, structured, analyzed, and presented in a format that supports real operational decision-making.

---

## 11. Diagram-Friendly Representation

For a visual diagram, the flow can be grouped into these blocks:

- Renewable Asset Data Sources
- ETL and Validation
- Operational Database
- Forecasting / Anomaly / Maintenance / Health Modules
- FastAPI Service Layer
- Streamlit Dashboard Layer
- User / Operator / Executive Actions

This structure is especially suitable for a simple flow diagram that can be embedded in presentations or architecture documentation.

---

## 12. Closing Statement

EOIP’s data flow is designed to move from raw operational signals to validated intelligence in a clear, auditable path. The result is a system that not only stores energy portfolio data, but also turns it into actionable operational insight through analytics, APIs, and dashboards.
